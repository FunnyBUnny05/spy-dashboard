# E3: Embedded vs Live Score Data Source Alignment Proposal

## Problem

The audit found a persistent ~4-point divergence between two score computations: `model.json.timeseries[-1]` reports score=25.84, while recomputing the same date live from `snapshot.ts` yields ~29.85. The root cause is a data-source split: the timeseries embedded in `model.json` was generated by the Python pipeline using FRED as the source for all macro signals, while `snapshot.ts` sources its live inputs from TradingView (for RSI, MFI, EMA distance), Yahoo Finance (for VIX, yield curve), and Vercel-hosted proxies (for PPI, margin debt). Because the underlying raw signal values differ between FRED and TradingView/Yahoo for the same calendar date, the composite score differs even when the scoring formula is identical. This is not a bug in the formula — it is an honest consequence of using different data vendors for historical vs live computation.

## Options Considered

1. **Re-run the timeseries generation script against TradingView/Yahoo sources:** Closes the gap permanently and ensures the history chart and the live score are on the same scale. Requires non-trivial Python pipeline work: exporting TradingView CSV history, wiring Yahoo Finance pulls into the batch script, and re-validating the walk-forward results against the new data.
2. **Document the gap explicitly in the UI:** Add a short note near the history chart stating that historical scores use FRED data while the live score uses TradingView/Yahoo, and that a ~4-point divergence at the boundary is expected. Immediately actionable, honest to the user, and requires no pipeline changes.
3. **Maintain two timeseries in `model.json`:** One FRED-based series for full history (1990–present), one TradingView/Yahoo-based series for the trailing 12–24 months where both sources overlap. Technically sound but adds complexity to both the Python pipeline and the TypeScript rendering logic, and the seam between the two series introduces a new visual artifact in the chart.

## Recommendation

**Option 2 — document the gap explicitly in the UI** is the right immediate action. The ~4-point divergence is real and not trivially eliminable without substantial pipeline work; presenting it honestly is better than silently blending two incompatible series. A small annotation near the history chart (for example: "Historical scores (pre-2025) use FRED data; the live score uses TradingView/Yahoo. A ~4-point boundary offset is expected.") gives sophisticated users the context they need to interpret chart continuity correctly. Option 1 is the correct long-term resolution and should be tracked as a P1 pipeline task — once TradingView/Yahoo history is available for all six active signals, the FRED-based timeseries should be retired. Option 3 should not be pursued: the seam complexity it introduces outweighs any benefit over the simpler documentation approach, and it does not eliminate the underlying source disagreement.
